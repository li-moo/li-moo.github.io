### 1. 컴퓨터 시스템 기본 구조

본문은 현대 컴퓨터 시스템의 기본 구조를 구성 요소 관점에서 분석하고, 각 하드웨어 부품이 수행하는 기능과 이들이 상호작용하며 프로그램을 실행하는 동작 원리를 설명한다. 특히 CPU, 메모리 계층 구조, 입출력 장치 및 운영체제와의 관계를 중심으로, 컴퓨터 구조가 소프트웨어 성능과 실행 모델에 미치는 영향을 고찰한다.
{: .notice--primary}

### 2. 서론

컴퓨터 구조(Computer Architecture)는 하드웨어 구성 요소의 조직 방식과 그 동작 원리를 연구하는 학문 분야이다. 이는 단순한 하드웨어 나열이 아니라, 프로그램이 어떻게 물리적 장치 위에서 실행되는지를 설명하는 중간 계층의 역할을 한다.
{: .notice--primary}
현대 소프트웨어 시스템의 성능은 알고리즘 자체뿐 아니라, CPU의 실행 방식, 메모리 접근 패턴, 캐시 활용, 저장장치 특성 등 컴퓨터 구조적 요소에 의해 크게 좌우된다. 따라서 컴퓨터 구조에 대한 이해는 운영체제, 자료구조, 컴파일러, 분산 시스템 등 상위 개념을 이해하기 위한 필수 기반이라 할 수 있다.
{: .notice--primary}

### 3. 컴퓨터의 기본 구조

현대 컴퓨터는 기본적으로 폰 노이만(Von Neumann) 구조를 기반으로 한다.
3.1 폰 노이만 구조의 특징

- 프로그램과 데이터가 동일한 메모리 공간에 저장됨
- CPU는 명령어를 순차적으로 인출(fetch)하여 실행
- 중앙 처리 장치가 시스템의 제어를 담당
- 이 구조는 단순성과 범용성이라는 장점을 가지지만, **메모리 병목(memory bottleneck)**이라는 근본적인 한계를 내포한다.

### 4. 중앙처리장치(CPU)의 구성과 기능

CPU는 컴퓨터 시스템의 핵심 연산 장치로, 다음과 같은 구성 요소로 이루어진다.
{: .notice--primary}

4.1 산술논리연산장치 (ALU)

- 산술 연산: 덧셈, 뺄셈, 곱셈 등
- 논리 연산: AND, OR, 비교 연산
- 조건 분기 판단의 근거 제공

  4.2 제어 장치 (Control Unit)

- 명령어 해석(decode)
- 데이터 이동 제어
- 각 하드웨어 장치에 제어 신호 전달

  4.3 레지스터 (Register)

- CPU 내부의 초고속 저장 공간
- 연산에 직접 사용되는 데이터 저장
- 프로그램 카운터(PC), 명령어 레지스터(IR) 포함

5. CPU 동작 원리: 명령어 사이클
   CPU는 다음의 **명령어 사이클(instruction cycle)**을 반복 수행한다.

- Fetch: 메모리로부터 명령어를 인출
- Decode: 명령어의 의미 해석
- Execute: 연산 또는 제어 수행
- Write-back: 결과를 레지스터 또는 메모리에 저장

이 과정은 초당 수십억 회 반복되며, 이를 최적화하기 위해 파이프라이닝과 병렬 실행 기법이 사용된다.

### 6. 메모리 시스템과 계층 구조

6.1 메모리 계층 구조

CPU와 저장장치 간의 속도 차이를 완화하기 위해 메모리는 계층적으로 구성된다.

```java
Register
Cache (L1, L2, L3)
Main Memory (DRAM)
Secondary Storage (SSD/HDD)

```

6.2 캐시 메모리
캐시는 자주 사용되는 데이터와 명령어를 저장하는 고속 메모리이다.

- 캐시는 캐시 라인 단위로 데이터를 관리
- 지역성(Locality) 원리에 기반하여 동작
- 시간 지역성
- 공간 지역성

캐시 미스 발생 시 CPU는 메모리 접근 지연으로 인해 성능 저하를 겪는다.

### 7. 주기억장치(RAM)의 역할

RAM은 실행 중인 프로그램과 데이터를 저장하는 공간이다.

- 휘발성 메모리
- CPU가 직접 접근 가능
- 스택과 힙 영역으로 논리적으로 구분됨

스택은 함수 호출과 지역 변수 관리에 사용되며, 힙은 동적 메모리 할당을 담당한다.

### 8. 보조기억장치(SSD/HDD)의 기능

보조기억장치는 데이터를 영구적으로 저장하는 역할을 한다.

- SSD: 빠른 접근 속도, 전자식 저장
- HDD: 대용량, 기계식 저장

보조기억장치는 CPU 연산에 직접 관여하지 않으며, 입출력(I/O) 장치로 분류된다.

### 9. 입출력 시스템과 인터럽트

입출력 장치는 CPU보다 현저히 느리기 때문에, 인터럽트 기반 동작을 사용한다.

- 장치 작업 완료 시 CPU에 신호 전달
- CPU는 현재 작업을 중단하고 I/O 처리 수행
- DMA를 통해 CPU 개입 최소화

이는 시스템 전체 자원 활용 효율을 향상시킨다.

### 10. 운영체제와 컴퓨터 구조의 관계

운영체제는 하드웨어 자원을 추상화하고 관리하는 계층이다.

- CPU 스케줄링
- 메모리 관리
- 프로세스 및 스레드 관리
- 파일 시스템 제공

운영체제는 컴퓨터 구조 위에서 동작하며, 구조적 특성에 따라 설계가 달라진다.

### 11. 결론 (Conclusion)

컴퓨터 구조는 단순한 하드웨어 구성 설명을 넘어, 프로그램 실행의 물리적 기반을 제공한다. CPU의 연산 방식, 메모리 계층 구조, 캐시 동작, 입출력 처리 방식은 모두 소프트웨어 성능과 직결된다.

따라서 효율적인 소프트웨어 설계와 성능 최적화를 위해서는 알고리즘 분석뿐만 아니라, 컴퓨터 구조에 대한 깊은 이해가 필수적이다. 현대 시스템에서의 성능 문제는 대부분 계산 능력이 아닌 메모리 접근과 구조적 병목에서 기인한다는 점에서, 컴퓨터 구조는 여전히 핵심적인 연구 대상이라 할 수 있다.
{: .notice--primary}
